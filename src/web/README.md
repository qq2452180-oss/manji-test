# 慢记 web

## manji 项目的本地开发

当前默认构建已连接 `src/api` 后端：章节和话题来自数据库，文字访谈、故事、传记及问答记录使用真实接口。首页底部“小暖”进入全局访谈；章节中的具体小标题（如“住过的地方”“常走的一条路”）是章节访谈入口。两者共用 `interview.html`，全局入口不带方向参数，章节入口携带 `topic_id` 和所属 `chapter_id`，以所选小标题为访谈方向。

全局访谈已接入文字和普通语音对话：点击“开始讲述”创建会话，小暖根据人物画像、经历索引和近期故事选择开场方向；没有记忆时从日常开聊。问答逐轮保存，可暂停、刷新或从“我的 → 讲述记录”继续。全局会话将 `interview_scope: global` 随记忆快照保存，恢复时不会被当作旧的无话题只读记录。本阶段用于调试访谈，尚未开放全局成稿归章。

章节访谈的具体小标题入口已接通文字和普通语音流程：选择话题后，点击“开始讲述”围绕该标题与小暖交流，结束后可整理成故事并保存到所属章节。两类访谈均需注册或登录账号，同一浏览器标签页内刷新会保留凭据；已有记录按原身份读取。

首页仅展示章节和话题，不再单列最近故事或继续上次讲述。已有正文的话题显示“已讲述”，点击直接打开故事；未结束的讲述和待整理内容仍从对应话题继续。进度来自 `/api/home` 的全量 `topic_progress`，不受最近五篇故事限制。

故事页的“继续补充”会绑定原故事，新讲述整理后更新同一个故事编号，原始问答和补充问答均保留。重复点击复用未完成的补充；整理失败可以继续，版本冲突时保留原文和补充素材，由用户选择“按最新故事重新整理”。暂时无法关联话题的旧故事仍可阅读。

升级已有数据库时，先运行 `python src/tools/run_sql.py migrate`，再重启后端。新增的 `0009` 只添加故事版本及补充记录，不修改前八个结构文件或重新生成旧正文；重复升级不会重置数据。

在项目根目录运行：

```sh
npm --prefix src/web ci
npm --prefix src/web run build
python -m uvicorn src.main:app --host 127.0.0.1 --port 8003
```

Python 环境需安装项目依赖，后端读取 `src/.env`。打开 `http://127.0.0.1:8003/web/index.html`，选择话题、开始讲述、输入文字，再点击“结束并整理”。整理会依次成文、更新记忆和生成摘要，故事直接保存到所选话题所属章节。页面刷新可读取已保存记录，整理失败可继续整理。

开发前端可运行 `npm --prefix src/web run dev`，`/api` 默认代理到 `http://127.0.0.1:8003`，可用 `MANJI_API_PROXY_TARGET` 覆盖。运行 `npm --prefix src/web test` 验证；`npm run build` 写入 `dist/`，FastAPI 在 `/web/` 提供该目录。

接口路由位于 `src/api/catalog` 与 `src/api/interview`，目录读取及访谈业务位于 `src/service/catalog` 与 `src/service/interview`。前端默认入口为 `src/connected-main.js`，接入页面位于 `src/pages/Connected*.vue`，API 与跳转封装位于 `src/lib/workflow-api.js`、`src/lib/workflow-navigation.js`。话题只提供名称和简短说明，开场与追问由访谈节点结合画像、经历索引生成。

`npm run build:html` 继续生成独立静态演示版 `dist-html/`，其演示素材与默认真实数据入口分开。

## 当前 RTC 后端与本地回调

通话业务集中在 `src/service/rtc/direct.py`，腾讯 SDK、入房签名和回调鉴权集中在 `src/common/tencent_rtc/client.py`。`src/api/rtc/` 负责配置与 HTTP 接口。通话状态只在单进程内存中保存，语音文字交给现有访谈服务，使用同一份对话历史；接通时通过腾讯 `WelcomeMessage` 播放最后一条模型回复，新访谈播放首问，重拨播放最新回复，不重复生成或保存消息。后端使用单实例、单 worker，重启后重新拨打。

配置项见 `src/.env.rtc.example`。本地联调时按上面的命令明确启动后端在 **8003**，网页打开 `http://127.0.0.1:8003/web/index.html`；回调也必须转到同一实例。

若使用 PyCharm 直接运行 `src/main.py`（当前端口 **8004**），网页也使用 8004，并在启动下方回调代理时加上 `MANJI_RTC_BACKEND_PORT=8004`，让通话创建和模型回调进入同一个后端进程。

另外分别启动回调代理和公网隧道：

```sh
python -m src.tools.rtc_callback_proxy
cloudflared tunnel --url http://127.0.0.1:18084
```

代理只允许两个精确的 POST 路径，转发到 `127.0.0.1:8003`：

- `/api/rtc/llm/chat/completions`：收到识别文字后生成本轮回答，使用专用 Bearer 凭据鉴权。
- `/api/rtc/events`：验证腾讯事件签名并确认收妥。

将 `src/.env` 的 `MANJI_LANGGRAPH_RTC_LLM_API_URL` 设为隧道 HTTPS 域名加 `/api/rtc/llm/chat/completions`，重启后端后新通话会将它传给腾讯。在腾讯控制台，将 AI 实时对话事件回调地址设为同一域名加 `/api/rtc/events`，密钥与 `MANJI_LANGGRAPH_RTC_CALLBACK_KEY` 一致。临时域名失效或变化时，两处地址都需要更新。

公网隧道只连接回调代理的 18084 端口。代理保持原始签名正文，正文上限为 256 KiB，不跟随上游重定向。无鉴权 POST 应返回 401；网页、登录及其他 API 路径应返回 404。

RTC 离线回归：`python -m pytest src/tests/test_rtc_*.py src/tests/test_member_rtc_access.py -q`。实际通话还需核对语音识别、模型回复、返回音频、历史保存和挂断。

## 安装与启动

使用 Node.js 24.12 或更新版本。在项目根目录执行：

```sh
npm --prefix web ci
npm --prefix web run build
MANJI_API_HOST=127.0.0.1 MANJI_API_PORT=8000 .venv/bin/python main.py --api
```

PyCharm 继续以项目根目录为工作目录，运行 `main.py`，参数 `--api`，使用 `.venv` 解释器；环境变量设置 `MANJI_API_HOST=127.0.0.1`、`MANJI_API_PORT=8000`。前端只需先构建，不要求另开网页服务。访问 `http://127.0.0.1:8000/` 或 `/index.html` 会保留查询参数并跳转到 `/web2/`，由新版页面判断首次体验或回访登录；根地址不再进入旧版 token 调试登录流程。Python 路由修改后需在 PyCharm 停止并重新启动服务。

修改前端时，在另一个终端运行：

```sh
npm --prefix web run build:watch
```

构建完成后刷新 8000 页面。监听构建保留前次哈希资源，普通 build 清理 dist；源码改动不自动热更新通话，避免意外重启麦克风。构建 watch 不替代 Python 服务。

## 目录与边界

- 根目录 HTML：16 个入口薄壳，共用 `src/main.js`，保留 `.html` 页面跳转。
- `src/pages`：首页、登录、访谈、历史、整理、传记/章节/故事、个人资料和家人预览。
- `src/components`：导航、页头、封面、鉴权照片预览、语音圆环和待提交照片。
- `src/composables`：Vue 页面生命周期与访谈控制器适配。
- `src/lib`：API、标签页存储、阅读/整理/访谈控制器、RTC 和字幕解析。
- `src/styles`：现有页面视觉样式及原型语音布局。
- `dist`：生成产物，FastAPI 只公开此目录。不得手动修改。

缺 dist 时仅 `/web2` 返回 503 构建说明，后端 API 不受影响；构建完成后刷新，无需重启 Python。旧版 `web-legacy` 与微信小程序不参与这次构建。目录首次改名后须重启原有 Python 进程，使静态目录指向新位置。

### 字幕诊断与验收

普通语音和图片访谈共用实时字幕。腾讯可能在一条消息里下发一整句或较长文本；控制器分开保存收到的原文和已展示的小段，按标点和词边界拆分，目标每段不超过 16 字（不拆英文单词）。第一小段立即出现，其余依次追加，同一时刻到达的多条消息也排队展示。同一句修订替换原内容及待展示的尾部，不重复追加全文。

显示节奏参考字幕起止时间；缺少有效时长时按阅读速度估算，每段间隔限制在 400–3000 毫秒。这是前端短语流式展示，不是逐字打字，也不保证与每个词的音频精确同步。圆环下的段落全部展开，自然换行，不设固定高度或内部滚动条。连接中的有效欢迎字幕和通话字幕优先于保存提示；尚未收到文字时显示“小暖正在说话…”。说完后保留本轮内容，下一轮开始思考或说话时停止旧队列，首段字幕到达时替换已显示内容。打断、暂停、隐藏、离开、换号和断开连接时清空字幕并取消队列，旧定时回调不能恢复显示。接收端仍在说完后 2 秒关闭尾句窗口，拒绝过期轮次的迟到消息；已接受的展示队列可继续完成。

排查时在访谈地址追加 `caption_debug=1`（已有查询参数时用 `&caption_debug=1`），在浏览器控制台筛选 `[manji-caption]`。诊断默认关闭，每个通话实例最多输出 200 条本地日志，包含收到、接受、丢弃的累计数量、固定原因码和消息字段类型；不记录对话正文、用户/轮次标识、令牌或签名，不上传诊断日志。原因码可区分身份/接收者不符、格式错误、过期轮次、重复或过期句子等情况。

自动回归验证字幕解析、单个长消息和突发多消息的分时展示、修订、乱序和清理规则。`tests/interview-caption-stream.test.js` 使用真实 Vue 页面、控制器和 RTC 消息解析，只模拟接口和媒体 SDK，检查首帧、时间推进与最终可见文字。实际设备上的声音和字幕节奏仍需人工验收。分别从“小暖”和“图片访谈”交流至少两轮，检查欢迎首段、逐段累积、说完保留、下一轮替换、打断、暂停继续和补图。

2026-10-08 14:20 的 Safari 真实诊断确认了丢失环节：收到 25 条消息，接受 6 条机器人状态，字幕接受数为 0；其中 4 条因 `invalid_receivers` 被丢弃。展开真实字幕记录可见 `receiver` 类型为 `undefined`，而字幕文字、轮次、起止时间与结束标记的类型均符合预期；消息已经通过当前机器人的传输身份和说话人校验。原解析器将省略 `receiver` 的有效字幕当成非法消息，导致有声音无文字。兼容该实际消息形态时，只允许省略字段；显式提供的接收者仍须为字符串数组，且为空或包含当前用户，`null`、其他类型、错误接收者和错误身份仍拒绝。

同日兼容修复后重新构建，Safari 复测记录已出现 `accepted_caption: 1`，确认真实字幕通过解析；本次相关适配器/控制器 96 项回归和 12 项静态构建检查通过。后续对话停在思考状态，模型桥接在 14:29:32–14:29:53 多次返回 HTTP 502，该类错误在 14:00:20 已出现。两条诊断通话已暂停并保留讲述。此阶段确认的是字幕接收恢复；连续两轮播放/字幕同步及图片访谈的真实验收仍未完成，不能将这次计数作为完整声音验收。

2026-10-08 修复后的自动验证：137 项 Vue 组件测试、117 项 Node 业务/字幕回归、12 项静态服务与构建检查通过，生产构建完成。使用实际 Vue 组件和合成数据检查 390×844、1280×800、320×480 三种尺寸下的欢迎、保存、长句、说话占位、图片访谈、暂停和失败共 21 个布局样例，无横向溢出或圆环/字幕重叠；长句键盘滚动与焦点可用。这些是界面与逻辑验证，不是实际声音同步证明。

登录凭据和业务指针沿用标签页 sessionStorage。语音恢复不会因刷新自动开麦，照片仅在明确继续后提交。退出、换号及页面隐藏均关闭通话，迟到回调不能重新开启声音。

## 首次进入与回访

首次欢迎页只有三句介绍和“开始”，不播放声音、不申请麦克风、不创建游客。文字按现有字幕的阅读节奏逐句出现，“开始”无需等待动画；减少动画时立即显示全文。体验选择页已删除，“开始”直接进入手机号验证码登录原型。

手机号登录目前仅为本地交互演示：输入 11 位大陆手机号，点击“获取验证码”后使用演示码 `123456`，60 秒后可重新获取，5 分钟内有效；修改手机号会使上一次验证码失效。校验成功展示“验证完成”，可点击“进入首页”打开独立的章节原型 `/web2/index.html?prototype=1`。不发送短信、不创建账号、不写入登录凭据，也不跳转到受保护的真实首页。已有正式账号可通过页面提供的链接继续使用。开发凭据入口只在登录地址带 `debug=1` 时显示，原账号密码后端接口保留。

演示版入口为 `/web2/index.html?prototype=1`，底部导航是人生地图、小暖、传记；居中的小暖按钮直接进入自由讲述，地图和传记右上角头像进入我的。人生地图使用桌面「开场」中的 V0.4 话题库，原样保存于 `src/content/life-stage-topics.json`：7 个人生时期各 12 题，另有横向主题 16 题，共 100 个话题、100 个入口问句和 300 个可选追问。`src/lib/life-map-topics.js` 按原目录、标题和问题顺序提供地图数据。地图卡片仅显示标题和入口问句，保留“讲过”标记与原有点击入口；不再展示“可选追问”。300 条追问仍完整保留在题库，供历史记录兼容与后续对话使用。原 `biography-template.json` 保留为旧故事与旧链接的兼容目录，地图不再显示旧 40 项。横向时间轴下，讲过的片段进入故事，未讲过的进入讲述；“讲过”只表示已有正文，不表示片段完成。传记直接展示自动更新的人生传记草稿，首屏开始阅读，不再展示大封面、目录或最近整理列表；保留阶段小标题，修订稿显示“修订初稿”，保留书名与正文。页面不再显示虚构、演示、示例等素材提示；我的显示“我的空间”，提供讲述记录、家人占位、重置内容和返回登录。

新话题点开后展示标题与对应入口问题，不再展示“看看其他问题”列表；新题尚未接入真实语音，不套用旧虚构回答；页面只保留当前标签页存储时限的必要提醒。点击开始后可先输入文字，草稿随输入保存在当前标签页；保存文字后可继续输入并保存多段补充，或结束并整理，不自动追加追问。整理仅按段落保留本人输入，不自动改写或生成故事事实；随后地图「讲过」、故事、讲述记录和传记同步更新。未保存的草稿需先保存再整理。刷新、离页后暂停，主动继续可恢复草稿；旧会话中已经选择的追问、回答与草稿保持原样。存储仍为原型 sessionStorage，关闭标签页后不保证保留，不写入正式账号或调用语音/AI接口。旧故事、补充、未结束讲述与旧URL继续使用原ID，不自动重新归类到新话题；旧记录保留在存储和原地址；新传记按新目录展示，未修改的旧示例不再重复入稿，已有修改与补充仍保留。

旧片段及自由聊仍使用以下固定脚本演示流程。

演示流程：选片段 → 开始讲述 → 暂停或结束并整理 → 约 2 秒整理 → 查看故事。讲述以 1.8 秒间隔展示固定字幕，不播放声音、不申请麦克风，不接短信或 AI。出现第一句用户示例后即可整理。每个片段都有对应脚本和成稿，来自 `src/content/prototype-scenarios.json`；自由聊固定归入“童年时光／记得的一件童年小事”。离页、隐藏或刷新后按暂停恢复，须主动继续。地图不再显示“接着上次讲”或“查看上次整理”快捷入口；未结束的讲述和草稿仍保留，可从“我的 → 讲述记录”继续。

`src/lib/prototype-state.js` 在独立的 `sessionStorage` 键 `manji.web2.prototype.v1` 中保存故事、记录和整理状态，不读写正式账号。新模板的示例位于 `src/content/life-map-demo-early.json`、`life-map-demo-later.json`：L1–L7、X 每类 3 篇，共 24 篇，同一位虚构文具店经营者的生活贯穿始终。每篇保留 4 条回答、3 段整理正文及 2 段传记编排稿；`src/lib/life-map-demo.js` 将源卡的入口和三个追问与回答组成 24 条已完成问答记录，共 96 组问答。地图中这 24 题显示“讲过”，单篇可进入对应示例问答，剩下 76 题可继续试写。新预置故事和问答均带 `source: fictional-demo`；UI 已按需求移除来源提示，但底层素材标识仍保留。它们不是实际用户资料或真实录音。

传记名为《把平常的日子记下来》。修订编排稿独立保存在 `src/content/life-map-biography.json`，按 L1–L7 的生活顺序形成七个叙事章节；地图仍保留七个时期加横向主题的八类题库。X03 老朋友融入少年章节，X05 货品记录本融入青年入行，X16 老店合影融入中年店务，默认传记不再单列“横向主题”。`passages` 可同时引用多个 `storyIds`，将重复的场景合并为一段连续叙述；24 篇来源各引用一次，原始问答、单篇正文及存储版本均不修改。

`src/lib/prototype-biography.js` 只在一个编排组的所有来源都存在、ID与话题匹配、正文的原始前缀完整时使用该组合并稿，本地追加按原文接在该组后面。缺失、删节、改写或错配的组合不使用合并稿，以免带入缺失来源的事实；已有素材逐篇退回原来的独立编排或修改后的原文。新增故事仍保留；已知的横向示例回到其对应人生时期，无法确认时期的其他横向故事保留在“另外记起的往事”，不凭题材猜测时间。`sources` 保留来源原章节 `chapterId`，合并组可以共享段落范围，配图仍按原来源查找。旧 `prototype-stories.json` 的 17 篇示例继续保留、旧 URL 仍可读；有新地图故事时，仅全文与标题完全未改的旧预置示例从传记投影中省略。旧记录如有改动、补充或不同 ID，继续展示。整个编排过程不写回源故事，不调用 AI 或后端。

演示素材更新使用 `seedRevision=4`，仍沿用独立的 `manji.web2.prototype.v1` 命名空间。从版本 3 升级时，在没有同话题故事或会话的位置补入新示例及对应已完成问答；已有内容、未结束讲述、草稿、ID、时间与补充均优先保留，绝不被示例替换。早于版本 3 的快照仍先兼容之前的旧示例扩充。读取不写入存储，重复读取一致，下一次正常保存带上当前素材版本。当前版本有意清空的内容不会重新填入。重置恢复 17 篇旧兼容故事、24 篇新故事和 24 条示例问答，并清空本地新增及未完成会话；旧整理回调不能重新写入。刷新即可看到新版，无需重置或清空浏览器数据。

四张静态配图位于 `src/assets/prototype-memories/`，由内置图像生成工具生成，图像主题与提示词记录在该目录的 `prompts.md`。图片只用于老巷、纸船、文具店和家庭日常的已存在故事，并在单篇阅读和传记的对应正文后显示，仅显示图片说明，不再展示“AI 演示配图”标签；不使用账号照片或图片上传接口。配图延迟加载并预留尺寸，加载失败隐藏图片，正文继续可读。

故事页的“查看这篇的问答”会携带故事来源，问答页顶部“返回故事”和底部“查看故事”均回到同一篇故事，刷新后仍保留返回路径；故事原来的章节、地图或讲述记录入口也继续保留。从讲述记录列表打开的问答仍返回记录列表。返回故事时只保留与该故事匹配且已完成的原会话，失效或不匹配的返回会话标识会被忽略。

所有原型内部链接保留 `prototype=1`，传递章节、片段及 `session_id`／`story_id`；来源由 `from=map|biography|chapter|history` 控制，只允许返回本地原型入口。无效或不匹配的标识显示返回入口，不展示别的片段正文。三栏导航仅出现在人生地图、传记和我的，细节页使用返回入口。原型不导入鉴权、上传、通话控制器；未带 `prototype=1` 的正式页面和接口保持原流程。

欢迎页和主页共用入口判断：验证有效的正式账号进入主页，已有游客进入登录／注册页并保留体验预览入口，确认过期的凭据进入登录页，网络失败停留重试。已看过欢迎页的匿名访客刷新或返回时进入登录页。整理结果与账号切回游客后的入口改为已有体验预览，不再跳转到已删除的体验页。

`manji.web2.welcome.seen.v1` 是浏览器级介绍已展示标记，存入 localStorage，另在 sessionStorage 保留降级副本；它不含账号数据，退出或换号时保留。旧版 `manji.web2.welcome.flow.v1` 仅作为已看过介绍的兼容信号，展示欢迎页或确认身份后清除，不再启用体验选择流程。登录凭据仍只使用原有 sessionStorage。清除浏览器数据或换浏览器可能再次显示欢迎；存储受限时，“开始”仍可直接打开登录页，不影响服务端身份校验。

### 麦克风与首次语音教学

新普通语音的授权、教学、正式对话在同一访谈文档内切换。授权说明可播报，但只有用户点击“开启麦克风语音聊”才调用麦克风权限；拒绝后提供浏览器设置说明、重试和文字退路。网页不调用小程序 `wx.openSetting`，不假定权限弹窗只能出现一次。后台返回须点击重新开启，刷新/历史返回不自动播放说明或开麦。

授权后的 `microphone-lease` 只持有本地音轨并采样音量，不创建云通话或上传语音。教学期间可暂停/重听讲解、查看全文或直接点击“准备好了，咱们开始吧”；点击后停止讲解，沿用访谈控制器创建/恢复会话，并将同一音轨交给 RTC，避免再次开麦。隐藏、离页、换号、切文字和失败均释放尚未交接的音轨；迟到的授权结果也会被关闭。正式对话的圆环沿用该音轨的真实 RMS 音量，减少动画设置下不缩放。

固定讲解位于 `src/assets/onboarding/`，公开文案为 `src/content/voice-onboarding.json`；播放器按每段音频结束切换字幕。浏览器拒播或音频加载失败时保留文字、手动播放及继续入口。需要更新配音时手动执行 `.venv/bin/python tools/build_onboarding_audio.py`，使用现有 TTS 配置生成静态素材，页面运行时无新增 TTS/API 请求。

`manji.web2.voice-guide.completed.v1` 单独记录本浏览器已主动完成/跳过教学，存储降级及换号保留规则与欢迎偏好一致，不代表浏览器已授予麦克风权限。本版只支持按钮跳过，不实现开口自动跳过或连接前语音缓存；教学阶段的声音不作为访谈材料。手机 Chrome/Safari 的实际授权、外放和与正式通话接续仍需真机验收。

## 两个语音入口

- 底部“小暖”：新建 GENERAL 普通语音；未完成教学时先显示授权和引导，已完成教学的主动进入沿用原连接方式；刷新、历史恢复和后台返回等待明确继续。
- 首页“图片访谈”：新建 PHOTO 图片语音，选图和上传不触发回复；点击“开始图片语音访谈”才提交照片并连接。首次失败重试保留同一请求编号，回复已生成但语音失败时只重连语音。
- 首页不展示“打字聊”，旧文字地址仍可使用。已建立访谈的暂停操作为“继续聊／传张照片／结束并整理”，与教学话术对应；未建立访谈时可点“不聊了”离开。

连接失败与主动暂停分别显示。重连会先核对旧通话保存结果；初始读取失败后保留已经创建的会话。新草稿按账号和 GENERAL/PHOTO 分开保存，旧草稿只有成功迁移且没有冲突才移除旧副本。
